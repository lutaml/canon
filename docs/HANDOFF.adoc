== Mechanics every team hits

[cols="1,3"]
|===
|Topic |The law

|Differential corpora
|Random-tree corpora never produce repeated keys or shared references —
shift/registration bugs survive 300/300 "green". Include linked shapes
(users-style rows). Lock byte-level fixtures to FILES (Ruby's fstring
interning varies per process).

|Performance claims
|Cross-wave serialbench comparison is INVALID (runner noise; pugixml
swung 1.7x between waves). Only within-run interleaved A/B on fresh
binaries counts. The perf gate is best-of-N per side.

|Release cuts (yeptris)
|`next_version` must be a LITERAL X.Y.Z. The release PR self-closes ~2
min after cut if checks never start: push a PARENTED trigger commit
(`git commit-tree -p "$sha" -m ... "$sha^{tree}"` — without `-p` the
commit orphans and the PR creation fails) within the window, then
approve runs gated at `conclusion == "action_required"` (the `status`
field reads `completed` while gated). The changelog gate requires an
`## [Unreleased]` section before EVERY cut, version-only ones included.

|Release cuts (yeptris-ruby)
|RELEASE_TOKEN unset -> the bump job's 60-min wait step always fails;
the PR opens anyway. Hand-merge on green, then dispatch the republish
with EMPTY next_version (reuses main's VERSION). A new gem version needs
its C `v<c_semver>` tag to EXIST first (platform legs vendor from it).

|Release cuts (leptris)
|The same cut/trigger/approve cycle; the Unreleased section exists on
main — keep it fed.

|Formatting
|The repos target clang-format 14+ (CI runs LLVM 18); local 11.1/22.1
both reject the config — the CI format job is the gate.

|CI flakes
|`pull_request` events intermittently vanish for fresh PRs (yeptris,
leptris). Fallback: `gh workflow run test.yml format.yml asan.yml --ref
<branch>` — sha-keyed check runs satisfy required-context protection.
A "failed" check may be CANCELLED by a concurrent push (concurrency
groups) — read the conclusion, `gh run rerun <id> --failed`.
|===
